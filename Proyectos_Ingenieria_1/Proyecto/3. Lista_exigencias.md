| 10/06/26 | E | **Función Principal:** El sistema tiene como función principal la gestión automatizada y remota del riego agrícola por gravedad. Utiliza nodos físicos remotos (ESP32 + LoRa) para capturar datos puntuales de humedad y NPK, los cuales alimentan un algoritmo de interpolación espacial en el servidor base. Este algoritmo estima las condiciones hídricas y nutricionales en áreas sin cobertura física de sensores, permitiendo al usuario visualizar el mapa de estado en una App y recibir alertas automatizadas, optimizando el recurso hídrico a un bajo costo de hardware.    | E.A |
| 8/04/26 | E | **Geometría:** El prototipo presenta una base de 30 cm x 15 cm y una altura aproximada de 10 cm, ya que dentro del prototipo estarán los componentes del sistema.  | L.N  |
| 8/04/26 | E | **Cinemática:** El flujo de agua debe ser controlado y medido en cada etapa de la planta.  | O.H  |
| 9/09/26 | D | **Fuerzas:** El flujo del riego debe mantenerse en un rango adecuado de 0.5 a 2bar para garantizar un flujo uniforme sin dañar el suelo ni las raíces. La fuerza del agua se controla mediante la relación presión-área (F=P·A). | L.N  |
| 10/04/26 | E | **Energía:**  Sistema de alimentación híbrida que prioriza la red eléctrica (adaptador 5V) y cuenta con una batería de litio (18650) como respaldo para zonas sin infraestructura. Incluye un módulo TP4056 para la gestión de carga y un sensor de voltaje que reporta el nivel de energía en tiempo real al aplicativo Blynk.| E.A  |
| 10/04/26 | E | **Materia:**<br><br>**Materia de ingreso:** Agua proveniente de un tanque o reservorio elevado, distribuida por gravedad. Debe estar libre de sólidos y cumplir condiciones adecuadas para riego. El sistema operará según la demanda hídrica del cultivo.<br><br>**Capacidad del sistema:** Distribución continua y controlada de agua (L/h) acorde al área de cultivo, sin uso de bombeo.<br><br>**Materia de salida:** Agua aplicada de forma uniforme al cultivo (riego por gravedad, surcos u otros). Se consideran pérdidas como evaporación, filtración y escorrentía, las cuales deben minimizarse mediante control automatizado.  | E.A  |
| - | E | **Señales (Información):** El sistema deberá contar con señales de entrada y salida para su operación automatizada.<br><br>**Señales de entrada:** Lecturas de humedad (GPIO 34/35), temperatura (One-Wire), datos seriales NPK (UART2), nivel de batería y comandos remotos desde la App. <br><br>**Señales de salida:** Activación de relé para la electroválvula, telemetría inalámbrica LoRa hacia el receptor y disparadores para el envío de alertas del sistema  | B.S  |
| 20/06/26 | E | **Control:** El sistema debe de permanecer estable en cada etapa del funcionamiento. Se gestionará la activación y lectura de los sensores de humedad, NPK y temperatura asegurando la recolección y transmisión de datos.  | E.D  |
| 11/04/26 | E | **Electrónico (hardware):** Arquitectura distribuida en dos nodos. 1) Nodo de Campo: ESP32 conectado a sensores de humedad, temperatura y NPK, alimentado por batería 18650 con gestión de carga TP4056 y elevador MT3608; utiliza LoRa SX1278 para transmisión. 2) Nodo Base: ESP32 receptor que acciona la electroválvula y utiliza conectividad Wi-Fi para enlazar los datos con el servidor de la App y las alertas. | L.N |
| 11/05/26 | E | **Software:** Algoritmo de control basado en umbrales: si la humedad o el NPK descienden del nivel óptimo, el software acciona la electroválvula autónomamente. Incluye integración con una plataforma IoT para el dashboard gráfico y rutinas de comunicación con la API de mensajería para el envío de alertas de estado y contingencia. | L.N  |
| 11/05/26 | E | **Comunicaciones:** Sistema de comunicación de dos niveles: 1) Red de Campo (LoRa): Enlace de radiofrecuencia de largo alcance y bajo consumo entre el nodo sensor y la base. 2) Red de Usuario (Wi-Fi): Conexión desde la estación base hacia la nube para la sincronización con la aplicación móvil y las alertas, garantizando acceso a la información desde cualquier lugar. | E.D  |
| 20/06/26 | E | **Normas y Leyes:** La implementación del sistema de riego automatizado por gravedad se sustenta en el marco legal peruano vigente orientado al uso eficiente del recurso hídrico, la protección ambiental y la seguridad operativa. En este contexto, la Ley N.º 29338 Ley de Recursos Hídricos establece la gestión sostenible del agua, promoviendo su uso eficiente en actividades agrícolas. Asimismo, el Decreto Supremo N.° 004-2017-MINAM define los Estándares de Calidad Ambiental (ECA) para el agua, asegurando que esta sea apta para riego. En relación con la seguridad del sistema, el Código Nacional de Electricidad Utilización regula las condiciones para instalaciones eléctricas seguras en sistemas automatizados. De igual forma, las normas técnicas desarrolladas por INACAL establecen criterios de calidad y seguridad para equipos electrónicos y de automatización. Finalmente, los lineamientos del SENASA promueven buenas prácticas agrícolas, incluyendo el uso eficiente del agua en sistemas de riego tecnificado. | B.S  |
| - | E | **Ergonomía:** El diseño del dashboard en Blynk se basa en la norma ISO 9241, asegurando una interacción hombre-máquina intuitiva. Se prioriza la legibilidad de las gráficas de humedad y niveles NPK, con controles digitales de fácil acceso para evitar errores operativos y fatiga visual del agricultor. La interfaz está adaptada para su uso en dispositivos móviles bajo condiciones de luz solar intensa, típicas del entorno agrícola.  | E.A  |
| 20/04/26 | D | **Fabricación:** Todos los componentes electrónicos del sistema, como la placa principal y la batería, irán guardados en una caja de plástico resistente y bien sellada para que no les entre agua, tierra ni se maltraten con el sol. Además, para que el equipo sea fácil de armar, revisar y transportar, las conexiones de los sensores se harán usando conectores simples o de tornillo. De esta forma, cualquier cable o pieza se podrá desconectar y cambiar rápidamente. Por último, para la estructura y el paso del agua se usarán materiales comunes y que no se oxidan, como tubos de PVC, garantizando que el sistema sea barato de armar, duradero y no contamine el terreno.   | L.N  |
| 20/06/26 | E | **Control de calidad:** El diseño, implementación y funcionamiento del sistema de riego automatizado debe contemplar todas las exigencias planteadas, con el fin de garantizar un desempeño eficiente y acorde a las necesidades del usuario. Se debe asegurar la correcta selección e instalación de sensores, así como la precisión en la interpolación de datos para una adecuada estimación de la humedad del suelo en todo el terreno.  | O.H  |
| 20/06/26 | D | **Montaje:** Instalación dividida por niveles de elevación para gestionar la gravedad. La ubicación de los nodos sensores se hará estratégicamente según la pendiente del terreno, permitiendo que el software ajuste la apertura de la electroválvula de forma diferente en cada nivel. Cada sección contará con tubería, sensores físicos directos y conexión LoRa al sistema central de control, así como con normas de calidad y gestión ambiental como ISO 9001 e ISO 14001.  | O.H  |
| 20/06/26 | D | **Transporte:** El sistema debe de contar con dimensiones y un peso que permita su transporte manual en entornos agrícolas.  | B.S  |
| 20/06/26 | D | **Uso:** Se contempla que el uso del sistema podrá darse bajo distintas condiciones ambientales, tales como altitud, relieve temperatura y humedad; presentes en las distintas regiones del país. Esto se tendrá en cuenta para la selección de actuadores, sensores, materiales y componentes electrónicos.  | E.D  |
| 20/06/26 | E | **Mantenimiento:** El sistema cuenta con tolerancia a fallos: si un sensor físico se daña, el algoritmo de interpolación espacial utiliza los datos de los sensores operativos restantes para estimar el valor faltante temporalmente, mientras se envía una alerta al usuario para el reemplazo físico del hardware  | L.N  |
| 20/06/26 | E | **Costos:** Podemos estimar un costo de diseño. Considerando los costos de los materiales (sensores de NPK, humedad y temperatura) así como los microcontroladores ESP32 y módulos LoRa, estimando un valor menor a s/500.00.  | L.N  |
| 20/06/2026 | E | **Plazos:** El proyecto empezará el Jueves 31 de Marzo y espera su finalización el Martes 30 de Junio. Se elaboró un dashboard en github para observar el flujo de trabajo, marcando las actividades a realizar y realizadas, como también las entregas principales con hitos marcados.  | L.N  |
